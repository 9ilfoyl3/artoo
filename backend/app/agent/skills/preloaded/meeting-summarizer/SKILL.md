# 纪要摘要师

把冗长的文档、会议记录或报告，提炼为重点突出、可执行的结构化摘要。

## 适用场景

当用户请求涉及以下内容时使用：
- "总结一下这份文档 / 报告"
- "提炼会议要点 / 生成会议纪要"
- "有哪些待办 / 行动项 / 决议"
- "帮我快速了解这份材料讲了什么"

## 工作流程

1. **判断范围**：明确要摘要的是整篇文档、整个知识库，还是某主题。涉及整个知识库或多份文档时，先调用 `list_documents` 获取权威文档清单；主题定位用 `search_knowledge`。
2. **选择读取路径**：
   - 多文档或全库摘要：调用 `search_knowledge(mode="summary")`，优先使用文档入库后异步生成的摘要制品。
   - 单文档精读：调用 `read_document`，按返回的 `next_offset` 继续读取，直到 `fully_read=true`。
3. **确认覆盖**：不得从搜索未命中推断文档不存在。报告未读取、不可用或超出范围的文档。
4. **分层提炼**：梳理结构，区分"核心结论""关键论据""决议事项""待办行动项"。
5. **输出结构化摘要**：按层次组织，重点在前。

## 输出格式

根据材料类型选用，常见结构：

```markdown
## 概述
一两句话说明文档主题与核心结论。

## 关键要点
- 要点一 [1]
- 要点二 [2]

## 决议 / 结论
- …

## 行动项（如有）
| 事项 | 负责人 | 期限 |
|------|--------|------|
| … | … | … |
```

会议纪要类材料若无负责人/期限信息，省略对应列或标"未明确"。

## 规则

- 摘要内容必须忠实于原文，**不可添加原文没有的观点或结论**。
- 区分"原文明确陈述"与"你的归纳"，归纳要合理且不偏离原意。
- 行动项只提取原文确实提到的待办，不凭空生成。
- 关键事实配行内引用 [1][2]，便于回溯原文。
- 控制篇幅，突出重点；用户要更详细时再展开。
