# Agent Note: PDF scan text-layer OCR deduplication

Status: implemented

## Problem

扫描 PDF 常见“整页栅格图 + 隐藏 OCR 文本层”结构。PDF loader 会同时提取页面文本层和
嵌入的整页图片。虽然已有文本时 pipeline 会跳过整份文档 OCR，但它仍会把每张嵌入图片
送去 OCR，并以 `[图片内容]` 追加结果。

因此，混合扫描页会在同一份文档中产生同一页的两个版本。文本层与新 OCR 结果来自不同
OCR 过程和不同输入形态，所以在空格、表格顺序或数字上可能不一致。

## Decision

对 PDF 扫描底图采用页级来源互斥。只有同时满足以下条件时，`PdfLoader` 才把嵌入图片
标记为 `is_page_background`：

- 页面提取文本层至少 80 个字符；
- 文本块面积至少覆盖页面的 1%；
- 文本块纵向跨度至少覆盖页面的 3%；
- 图片显示区域至少覆盖页面的 70%；
- 至少 60% 的文本层字符位于图片区域内。

`DocumentPipeline._process_embedded_images` 会把整页扫描底图排除在嵌入图片 OCR 之外。
该页的隐藏文本层成为唯一权威文本。

纯扫描件与普通嵌入图片保持原行为：页面没有可用文本层时，扫描图仍进入既有的整份文档
OCR 路径；图片是普通图表或截图时，仍会 OCR 并追加。

## Alternatives considered

**在原生文本和 OCR 文本都产生后再做模糊去重。** 已否决，因为不同 OCR 引擎在空格、
阅读顺序和表格重建上差异很大，相似度阈值脆弱，而且仍会付出 OCR 成本。

**页面只要存在任何文本就跳过全部嵌入图片 OCR。** 已否决，因为混合页面本来就需要从
图表、截图和插图中提取有效文本。

**总是重新 OCR 整页并丢弃嵌入文本层。** 已否决，因为现有文本层往往准确，这样做既增加
成本，又会用未验证结果替换已知可用的来源。

## Consequences

混合扫描页不再重复正文，也避免一次不必要的 OCR 请求。该启发式规则有意保持保守；
只要未满足全部阈值，页面仍保留旧行为。满足阈值的低质量文本层会被信任；本次改动没有
页面级质量覆盖开关，也不比较 OCR 置信度。

`EmbeddedImage.is_page_background` 是 pipeline 内部字段，不改变 Open API、持久化
chunk schema、文档元数据契约或清理行为。

## Testing

`backend/tests/test_pdf_scan_text_layer.py` 生成合成 PDF，并验证：

- 具有可用文本层的整页扫描图不会被再次 OCR；
- 强制旧行为时仍能给出重复内容的对照输出；
- 文本页中的小型嵌入图片仍会 OCR 并追加；
- 只有一行说明的整页图片仍会 OCR；
- 纯扫描图仍可进入整份文档 OCR。
