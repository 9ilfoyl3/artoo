# Agent Note: global default agent preset

Status: implemented

## Problem

`agent_presets.is_default` 已存在，但智能体配置页没有提供修改入口，因此内置
「智能推理」实际上被固定为默认。现有写入路径还把默认变更限制在预设创建者范围
内，而问答选择却把 `is_default` 当作全平台唯一的默认项。历史数据因此可能存在
零个或多个默认项，平台超级管理员也无法用平台级自定义预设替换内置默认。

## Decision

`is_default` 表示全平台唯一的默认智能体预设：

- `PUT /api/agent-presets/{preset_id}/default` 使用 `require_platform`，会清除
  其他所有预设的该标记，并把选中的内置或平台级预设设为唯一默认。
- 智能体页面在非默认卡片的星标操作中向平台超级管理员提供入口。当前全局默认继续
  使用已有的实心星标和「默认」Badge。
- 面向普通成员的创建和更新请求会拒绝任何修改 `is_default` 的尝试；租户自有预设
  仍属于租户配置，不能成为平台默认。
- `_ensure_builtin_presets()` 会把遗留状态收敛为恰好一个默认项：存在内置智能推理
  默认时优先保留，否则保留最早的现有默认项；没有任何默认项时回落到智能推理。
- 删除当前全局默认后，内置「智能推理」会重新成为默认。

修改内置预设的默认状态使用专用接口，而不经过普通更新接口，因此内置配置仍保持
不可修改。

## Alternatives considered

**继续按预设创建者分别维护默认项。** 否决：问答页面只选择一个可见默认项，多个
创建者级默认会产生歧义，也可能导致平台默认实际上没有被替换。

**允许通过普通编辑接口修改内置预设。** 否决：默认选择属于平台策略，而内置配置
需要保持不可修改并跨租户共享。

**在 `PlatformConfig` 中存储预设 id，而不使用 `is_default`。** 否决：现有
`is_default` 已承载该选择并被问答链路使用；本次应修正其作用域，避免数据库迁移
和第二份真值来源。

## Consequences

默认选择在各租户间保持确定，并通过独立权限边界在预设变更后继续有效。无需数据库
迁移，遗留的多默认记录会在现有内置预设保障路径中被收敛。普通租户成员会失去此前
实现的按创建者默认行为；该行为没有界面入口，且与问答选择冲突。租户自有预设无法
成为全局默认，因为平台超级管理员看不到租户私有预设。
